# Dual Production Deployment (Russia + Hetzner)

Eternal World runs as **two completely independent production installations**.
They share GitHub source and GHCR images only. They never share databases,
Redis, Qdrant, media, backups, secrets, or volumes — except the optional
host-wide Hugging Face model cache `shared_huggingface_cache` on each server
(same pattern on Russia and Hetzner so multiple AI projects can reuse model weights).

| | Russia | Hetzner |
|---|---|---|
| Domain | `eternalworld.lukiora.ru` | `eternal.world.lukiora.com` |
| Server | existing RU host | `77.42.74.23` |
| App dir | `/opt/eternal-world` | `/opt/eternal-world` |
| Compose | `docker-compose.prod.yml` | `deploy/hetzner/docker-compose.yml` |
| Compose project | `eternal-world` | `eternal-world-hetzner` |
| HF model cache | `shared_huggingface_cache` (external) | `shared_huggingface_cache` (external) |
| Backend loopback | `127.0.0.1:8033` | `127.0.0.1:8133` |
| Frontend loopback | `127.0.0.1:3017` | `127.0.0.1:3117` |
| GitHub Environment | `production-russia` | `production-hetzner` |
| Nginx templates | `infra/nginx/eternalworld.lukiora.ru*.conf` | `deploy/hetzner/nginx/` |

Production branch: `staging/eternalworld-lukiora-20260715`.

Workflow: `.github/workflows/deploy-production.yml`.

Legacy Russia-only manual workflow (unchanged): `.github/workflows/deploy-staging.yml`.

## Architecture

```text
Push / workflow_dispatch
        │
        ▼
   prepare (target flags)
        │
        ▼
   validate (compose + pytest + frontend typecheck)
        │
        ▼
   build-and-push  ──► GHCR once per commit SHA
        │
        ├──► deploy-russia   (if target includes russia)
        └──► deploy-hetzner  (if target includes hetzner)
```

Images built once per commit:

- `ghcr.io/lakyn80/eternal-world-backend:<full-git-sha>` (+ short SHA + `latest`)
- `ghcr.io/lakyn80/eternal-world-frontend:<full-git-sha>` (+ short SHA + `latest`)
- Shared AI base: `ghcr.io/lakyn80/python-ai-base-py312:py312-v1`

Production always deploys the **full commit SHA** tag, never `latest` alone.

Frontend is built with empty `VITE_API_URL` so one image works behind both
domains via same-origin `/api` through Nginx.

## GitHub Environments and secrets

Create two Environments in the repository settings:

1. `production-russia`
2. `production-hetzner`

Identical secret **names** are fine because Environments isolate values.

### Required on both Environments (SSH)

| Secret | Purpose |
|---|---|
| `DEPLOY_HOST` | Server IPv4 or hostname |
| `DEPLOY_USER` | SSH user (often `root`) |
| `DEPLOY_SSH_KEY` | Private SSH key (never commit) |
| `DEPLOY_PORT` | Optional; defaults to `22` |

Suggested values:

- Russia `DEPLOY_HOST`: existing RU host (historically `188.120.231.45`)
- Hetzner `DEPLOY_HOST`: `77.42.74.23`
- Both `DEPLOY_PATH` is fixed in the workflow as `/opt/eternal-world`

### Hetzner app secrets (for first-time seed only)

If `/opt/eternal-world/.env.prod` is missing, the workflow can seed it from:

| Secret |
|---|
| `POSTGRES_DB` |
| `POSTGRES_USER` |
| `POSTGRES_PASSWORD` |
| `JWT_SECRET_KEY` |
| `AI_BRAIN_PROVIDER` |
| `AI_BRAIN_BASE_URL` |
| `AI_BRAIN_MODEL` |
| `AI_BRAIN_API_KEY` |
| `CONTENT_TRANSLATION_PROVIDER` |
| `CONTENT_TRANSLATION_BASE_URL` |
| `CONTENT_TRANSLATION_MODEL` |
| `CONTENT_TRANSLATION_API_KEY` |
| `LETSENCRYPT_EMAIL` (optional) |

Use **different** DB passwords and JWT secrets than Russia. Do not copy Russian
production credentials.

### Russia secrets policy

The dual workflow **does not overwrite** Russia `/opt/eternal-world/.env.prod`.
It only patches image tags / ports / CORS. SSH secrets above are still required.
Optional `LETSENCRYPT_EMAIL` may be set for cert renewal paths.

Map historical repo secrets if needed for the legacy `deploy-staging.yml` only:

- `STAGING_SSH_PRIVATE_KEY` → keep for legacy workflow
- `STAGING_POSTGRES_*`, `STAGING_JWT_*`, `STAGING_AI_*`, `STAGING_CONTENT_*`

## Automatic push deploy

A push to `staging/eternalworld-lukiora-20260715` runs:

1. validation/tests
2. one GHCR build for that commit SHA
3. deploy Russia
4. deploy Hetzner

Both targets receive the same immutable SHA image tags.

## Manual deploy (`workflow_dispatch`)

Input `deployment_target`:

- `both` (default)
- `russia`
- `hetzner`

Actions → **Deploy Production** → Run workflow → choose target.

## GHCR packages

Packages are published automatically by `build-and-push` using:

- `docker/login-action`
- `docker/metadata-action` (OCI `org.opencontainers.image.source` / `revision`)
- `docker/build-push-action`

Ensure the GitHub Packages visibility/permissions allow the deploy runners and
servers to pull. Servers authenticate with the ephemeral `github.token` passed
into `docker login` during deploy (same pattern as the legacy staging workflow).

## First Hetzner installation

On `77.42.74.23` (do not disrupt `rag.lukiora.com`):

```bash
sudo mkdir -p /opt/eternal-world
sudo chown "$USER":"$USER" /opt/eternal-world
cd /opt/eternal-world
```

Copy repo files (or let the first successful workflow copy them), then create env:

```bash
# From a machine with the repo:
scp deploy/hetzner/docker-compose.yml root@77.42.74.23:/opt/eternal-world/docker-compose.yml
scp deploy/hetzner/.env.example root@77.42.74.23:/opt/eternal-world/.env.example
scp -r deploy/hetzner/nginx root@77.42.74.23:/opt/eternal-world/nginx
scp deploy/hetzner/remote-deploy.sh root@77.42.74.23:/opt/eternal-world/remote-deploy.sh
```

On the server:

```bash
cd /opt/eternal-world
cp .env.example .env.prod
nano .env.prod   # set unique POSTGRES_*, JWT_*, AI_* keys; leave ports 8133/3117
```

Install Nginx site (HTTP bootstrap for Certbot):

```bash
sudo cp /opt/eternal-world/nginx/eternal.world.lukiora.com.bootstrap.conf \
  /etc/nginx/sites-available/eternal.world.lukiora.com
sudo ln -sfn /etc/nginx/sites-available/eternal.world.lukiora.com \
  /etc/nginx/sites-enabled/eternal.world.lukiora.com
sudo nginx -t && sudo systemctl reload nginx
```

Issue TLS:

```bash
sudo certbot --nginx -d eternal.world.lukiora.com
```

After GitHub Environments/secrets are configured, run **Deploy Production** with
`deployment_target=hetzner` (or wait for a push that deploys both).

Safe compose commands only:

```bash
cd /opt/eternal-world
docker compose --env-file .env.prod -f docker-compose.yml pull
docker compose --env-file .env.prod -f docker-compose.yml up -d --remove-orphans
```

**Never** run `docker compose down -v`.

## Verify health

```bash
docker compose --env-file .env.prod -f docker-compose.yml ps
curl -fsS http://127.0.0.1:8133/health/runtime
curl -I http://127.0.0.1:3117/
curl -I https://eternal.world.lukiora.com/
```

Russia equivalents use ports `8033` / `3017` and `docker-compose.prod.yml`.

## Rollback (no data deletion)

1. Pick a previous commit SHA that was built to GHCR.
2. Run **Deploy Production** on that commit (`workflow_dispatch` from the Actions UI
   on the desired commit, or temporarily redeploy after checkout of that SHA).
3. Or on the server, set:

```bash
BACKEND_IMAGE=ghcr.io/lakyn80/eternal-world-backend:<old-full-sha>
FRONTEND_IMAGE=ghcr.io/lakyn80/eternal-world-frontend:<old-full-sha>
```

then `docker compose pull` + `up -d --remove-orphans` (no `-v`).

Volumes and databases stay intact.

## Data isolation rules

Do **not** implement between Russia and Hetzner:

- DB replication
- shared object storage
- cross-region backups
- shared Redis / Qdrant
- shared `.env` / encryption keys

Future Russian data-residency work is separate.
